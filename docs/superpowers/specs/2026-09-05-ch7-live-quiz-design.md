# R2 Ch7 가면무도회 구현 계약

R1 완료 후 구현할 승인 로드맵의 Ch7 완결 배치. 기준은 기존 6챕터·라이브 어댑터·가면 표시/행동 identity 분리다. 새 엔진이나 별도 토너먼트 시스템을 만들지 않는다. Fable 사전 검토 후 총괄 판정으로 구현한다.

## 사용자 흐름

- 2막 3챕터 완주 후 3막 Ch7이 열린다. 3막 안의 순서는 이후 Ch8/9가 추가돼도 강제하지 않는다.
- 비비안의 도입 씬 → 상대 유형 레슨/드릴 → 가면 4명과 관찰 대결 → 가면 퀴즈 4문항 → 서버가 정체 공개 → 드러난 상대에게 맞춰 대결 → 결산.
- 가면 퀴즈는 반드시 4문제를 제출하고 최소 3문제를 맞혀야 한다. 무응답은 서버 시간 만료 시 오답이다. 한 문제만 맞히고 나머지를 건너뛰어 통과할 수 없다.
- 관찰 12핸드와 정체 공개 후 최대 10핸드는 같은 sparring 스텝의 두 구간이다. 재도전하면 관찰/퀴즈도 다시 시작한다. 잘못 푼 퀴즈를 앞 성공 스텝에 보존해 재도전이 영원히 실패하는 구조를 피한다.
- 정체 공개 후 판정 가능한 결정 2회 이상, 그중 좋은 결정 50% 이상을 통과 조건으로 둔다. 승패·칩 증가로 통과를 판정하지 않는다. 이 목표는 다음 절의 상대 대응 규칙으로 판정한다.
- 시험 모드는 기존과 같이 드릴 85% 통과이며 라이브 퀴즈와는 구분한다. Ch7 하나의 시험 통과로 3막 전체 승급은 발생하지 않는다.

## 가면과 공개 정보

- 실제 성향 풀은 모찌/초코/구미/클로이, 표시 캐릭터는 기존 masked 캐릭터와 가면 A~D 이름이다. 풀의 좌석 배정은 서버에서 한 번 CSPRNG로 섞는다. 공개 챕터 TS에 실제 좌석→성향 정답표를 고정하지 않는다.
- `LiveTableSpec`에는 가면 정책 식별자와 표시 좌석만 둔다. 서버 전용 정책이 pool/셔플/정답/해설을 소유한다. `validateChapters`는 지원 정책·좌석 수·중복·단계 설정을 검사한다.
- 최초 `buildBotIdentityPlan`에서 확정한 계획을 room-lost 재개에도 보존한다. 새 runId의 재도전은 새 계획을 만든다. 테스트에는 shuffle 함수 주입을 허용한다.
- 공개 gameState·story-update·채팅·핸드 히스토리·botThoughts에는 공개 전 실제 성향 ID/이름이나 숨겨진 홀카드를 싣지 않는다. 내부 로그에도 정답표를 기록하지 않는다.
- 관찰 중 공개 액션에서 계산한 표본 수·참여/레이즈/콜 빈도만 관찰 노트로 보여 준다. 실제 personality의 설정 HUD 수치를 곧바로 공개하지 않는다. 작은 표본의 불확실성을 레슨에서 설명한다.
- 속마음은 Ch7 가면 구간에서 노출하지 않는다. 정체 공개 뒤에도 현재 핸드의 숨겨진 카드/전략을 즉시 읽어 주지 않는다. 종료한 핸드의 교육용 설명만 공개된 사실로 생성한다.

## 퀴즈 상태와 명령

- 어댑터가 손 경계에서 `observing → quiz → revealed-play`를 소유한다. 관찰 12핸드가 끝나면 다음 핸드를 hold하고 질문을 발급한다. 현재 핸드의 액션 타이머를 중간에 멈추는 기능은 R2에 추가하지 않는다.
- 질문은 opaque quizId, 가면 좌석/표시 이름, 질문, 선택지 4개, `expiresAt`, 현재 번호/필수 문제 수만 공개한다. 정답·해설은 채점 전 DTO에 없다.
- 신규 질문마다 서버 deadline 30초. 테스트 now/timer 주입. 재접속은 같은 질문 ID와 deadline, 선택지 순서를 받는다. 타임아웃과 사용자 답 중 먼저 접수한 하나만 확정한다.
- 기존 `answer-story-quiz`는 `{runId, quizId, optionIndex}` strict parser를 사용한다. 세션 소유권·프로필·현재 런·활성 질문·선택지 경계를 검증하며 `story` rate limit를 적용한다. 클라 정답/점수/성향 ID를 받지 않는다.
- 채점 후 피드백(내 선택/정답/짧은 근거)과 해당 가면의 공개 정보를 보낸다. 서버 `revealBotIdentity` seam만 정체를 바꾼다. 일반 플레이 액션은 공개를 수행할 수 없다.
- 같은 quizId의 동일/다른 선택 재전송은 첫 채점 결과를 반환하며 점수·정체 공개를 반복하지 않는다. 현재 런에 발급한 최대 4개 영수증만 보관한다. 다른 runId 또는 모르는 quizId는 거절한다.
- [계속]은 기존 `story-advance target:'resume'`를 통해 채점 피드백을 확인한 뒤 다음 문제로 간다. 미응답 질문의 resume은 거절한다. 마지막 피드백 확인 후 4문항 제출 상태를 검사하고 revealed-play로 재개한다.
- quiz 대기 중 외부 room-lost가 오면 quiz ID/마감/정답 상태를 보존한다. 방 재개 시 identity 계획·공개 여부와 quiz hold를 복원한다. 보존된 질문이 있는 동안 `openRoom`이 clearHold/resumeRoom을 무조건 실행하지 않도록 구분한다.
- abandon·완주·shutdown은 질문 타이머/영수증을 정리한다. offline 중 deadline은 지나갈 수 있지만 이미 틀린 문제를 계속 새로 발급하지 않는다. 피드백에서 사용자 확인을 기다린다.
- 필수 4문제를 서버 오류로 발급하지 못한 경우 정상 통과로 처리하지 않는다. 복구 가능한 hold나 명시적 실패로 남긴다. 기존 일반 목표의 기회 없음(null) 정책을 전역 수정하지 않는다.

## 상대 대응 목표

- 기존 `reviewHand`는 일반 프리플랍/가격 판정만 하며 상대 유형 대응 기능은 아직 없다. 그 결과를 이름만 바꾸어 Ch7 상대 대응 점수로 사용하지 않는다.
- 서버 전용으로 현재 히어로가 아는 상대 유형과 공개 액션, 내 홀카드, 그 스트리트 보드만 사용한다. 상대의 비공개 실제 홀카드는 정답 근거에 포함하지 않는다.
- 명확한 학습 규칙이 있는 기회만 집계한다: 콜링 스테이션 상대 톱페어+ 리버 밸류벳, 정직한 강한 공격 상대 약한 핸드 폴드, 블러프가 잦은 상대의 합리적인 크기 벳에 톱페어+ 콜. 다중 상대/모호한 가격/상황은 판정 제외한다.
- 규칙과 임계값은 순수 공용 평가 함수 하나로 두어 설명/목표가 일치하게 한다. 상대 유형별 좁은 예시와 배드빗/승리 반증 테스트를 포함한다. 후속 Ch8~10이 이 기회별 판정을 확장할 수 있다.
- 강한 핸드의 폴드나 무조건 폴드만 반복해서 모든 목표를 통과하지 않도록 최소 실행 횟수를 검증한다. 카드 분포 때문에 기회가 끝내 없으면 결과에 미측정 이유를 표시하며 별도 횟수 조건은 면제하지 않는다.

## 챕터·보상·부분 막 공개

- 신규 `act3/ch07-masquerade.ts`에 씬/레슨/가면 관찰 설명/드릴 7문항(상대 유형 5 + 액션 2)/sparring/실패 씬/에필로그/result를 등록한다. 문구는 비비안 말투와 원어 포커 용어 규칙을 지킨다.
- 첫 완주 도장 XP 250, 비비안 인연 100, 재도전/등급은 기존 명세의 경제량을 사용한다. 기존 밀리 단위를 유지한다.
- 새 보상 칭호·CG/의상 등은 `rewards/catalog.ts`와 R1a v34 다음의 v35에 함께 추가하고 DB/TS parity를 검사한다. 실제 이미지 파일이 없으면 기존 정지/스프라이트 폴백을 사용하며 없는 파일을 AVAILABLE에 등록하지 않는다.
- `isActCompleted`의 "현재 등록된 act 챕터 모두"는 Ch7 단독 배포에 부적합하다. `curriculum.ts`에 4막×3개 정식 ID 목록을 정의하고 완주 판정은 필요한 ID 전체 등록+완료를 요구한다. 서버 보상 서비스/띠/UI가 같은 기준을 사용한다. 테스트용 임의 챕터 배열에도 기대 커리큘럼을 명시해 기존 fixture의 의미를 보존한다.
- Ch7 완료만으로 brown/act3 rewards를 주지 않는다. Ch8/9까지 완료되면 갈색띠가 나온다. Ch12 검은띠는 여전히 4막 완료+졸업 ITM 플래그다.

## 구현과 검증 분할

1. 퀴즈·정체·상대 대응 순수 정책과 실패/무응답/중복 테스트.
2. live adapter 소유권/질문 deadline/room-lost/공개 seam, coordinator의 answerQuiz 및 socket handler 연결. 일반 방 훅 호출 수 0 회귀 유지.
3. `HandReadQuizView`/피드백 DTO, story-store ACK 잠금, `StoryOverlay` 퀴즈 카드/관찰 노트, 모바일 스크롤·키보드·오프라인 UI.
4. Ch7 씬/드릴/라이브 목표, 해금/고정 커리큘럼, 보상 카탈로그/마이그레이션.
5. 실소켓으로 4문항 중 1개만 정답·전부 timeout·3개 정답·중복/구 quizId·다른 프로필·room-lost 복구·보상 중복을 검증한다. 운영자 skip만으로 완주 검증을 대신하지 않는다.
6. 모바일/데스크톱 실제 브라우저에서 문제→선택→피드백→정체 공개→대결 재개, 실패 재도전과 시험 경로를 확인한다.

공유 `views/types/coordinator/adapter/socket/objectives` 파일은 한 구현자가 소유한다. 드릴/챕터/보상 작업을 병렬화한다면 서버 계약 커밋 이후 별도 파일 소유권을 정한다. Fable은 정답/identity 누출, 미응답 우회, 재접속 시 핸드 재개 경합, 부분 막 승급을 우선 반증한다.
