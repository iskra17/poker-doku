# 신규 CG 다양화와 RTX 5090 상시 제작 기획

2026-09-05 사용자 플레이 피드백 ④·⑤ 반영. 기존 이미지 교체는 범위 밖이며, 아래 기준은 새 이미지·이벤트 CG에 적용한다. 이 문서는 제작 설계다. GPU 배치 실행이나 게임 내 새 CG 배포를 완료했다는 뜻은 아니다.

## 1. 목표와 현재 자산

- 목표: 같은 얼굴을 정면에서 반복하는 이미지를 줄이고, 캐릭터별 상황·시선·감정이 다른 장면을 꾸준히 공급한다.
- 현재 게임: 6챕터, 영상 매니페스트 49클립. 클립 숫자를 늘리는 것과 새로운 장면을 늘리는 것을 별도로 측정한다.
- 확인한 GPU: RTX 5090, 표시 VRAM 32,607 MiB. 기존 작업 기록에서 H3 768×1152 루프는 대략 95~120초/클립이었으나 정지 이미지 생산 속도는 새로 실측한다.
- 설치 확인: `D:/AI-Image-Video/models/checkpoints/animagine-xl-4.0-opt.safetensors`, IP-Adapter Plus/Plus Face SDXL, OpenPose SDXL, MiniMax H3.
- 기존 참조 워크플로: `C:/code/1. codex/AI-Image-Video/workflows/character-consistency-face-lock-openpose-v3.json`, `character-consistency-ipadapter-dual-reference-v2.json`. 다른 프로젝트 캐릭터 입력을 그대로 쓰지 않고 Poker Doku 전용으로 복제·교정한다.

## 2. 선택한 제작 방식

| 방식 | 장점 | 제약 | 선택 |
|---|---|---|---|
| 문장·seed만 바꾸기 | 바로 시작 가능 | 동일 정면 구도 반복과 정체성 흔들림을 제어하기 어려움 | 탐색용만 |
| 얼굴 참조 + 별도 포즈/구도 + 장면 목록 | 현재 설치 환경 재사용, 변화와 동일 인물 판정을 따로 관리 가능 | 초기 참조/포즈 검수 필요 | 1차 권장 |
| 캐릭터별 LoRA 학습 | 일관된 정체성을 반복 호출하기 편함 | 다양한 정답 학습셋이 먼저 필요, 정면뿐인 데이터는 정면 편향을 학습 | 충분한 승인 이미지 확보 후 검토 |

IP-Adapter의 영향은 가중치와 적용 구간에 따라 달라지며, 원본 전체 이미지의 구도까지 강하게 가져올 수 있다. 얼굴·색채 참조와 장면 구성 참조를 분리하고 3개 강도 후보를 비교한다. OpenPose는 주로 몸 자세를 제어하므로 얼굴 방향은 머리 랜드마크·측면 참조·텍스트 조건을 함께 검수한다. 이 조합이 현재 캐릭터의 동일성을 보장하는지는 파일럿으로 확인해야 한다.

근거: [IP-Adapter 노드 설명](https://github.com/cubiq/ComfyUI_IPAdapter_plus/blob/main/NODES.md), [ComfyUI ControlNet 설명](https://docs.comfy.org/tutorials/controlnet/controlnet).

## 3. 새 이미지의 연출 규칙

캐릭터 외형 고정값(얼굴 윤곽·머리/눈 색·고유 장신구)과 장면 변화값을 별도 기록한다.

| 축 | 장면 목록에서 선택할 값 |
|---|---|
| 얼굴 방향 | 좌/우 3/4, 옆얼굴, 고개를 돌려 돌아보기, 아래/위 시선, 정면 |
| 시선 대상 | 상대 캐릭터, 카드/칩, 소품, 창밖, 카메라 |
| 프레이밍 | 표정 클로즈업, 허리 위, 전신, 어깨 너머, 인물+환경 와이드 |
| 동작 | 칩 정리, 카드 확인, 의자에 기대기, 걷기, 악기/책/찻잔 다루기 |
| 감정 | 집중, 의심, 안도, 놀람, 자신감, 웃음, 수줍음, 생각에 잠김 |
| 조명/장소 | 오후 도장, 비 오는 창가, 정원 야간, 무대 뒤, 옥상, 조용한 카페 |

첫 36장 기획의 목표는 정면 20% 이하, 카메라 응시 30% 이하이다. 이는 모델 성능 보장이 아니라 편집 기준이다. 같은 캐릭터의 연속 공개작은 방향·동작·프레이밍 중 최소 2개가 달라야 한다. 2인 CG는 장식적인 병치보다 행동과 시선의 관계를 먼저 지정한다.

참조 자료는 캐릭터별 기존 정본 이미지와 함께 **새로 승인한** 좌/우 3/4·측면 이미지를 묶는다. 같은 정면 그림을 증식해 학습시키지 않는다. 게임 원본 파일은 교체하지 않는다.

## 4. 첫 제작 배치 — 후보 144장, 새 장면 36종

대상은 기존 성인 히로인 6명이다: 사쿠라 22, 아라 21, 하나 24, 클로이 23, 비비안 26, 엘레나 27세(캐릭터 데이터 기준).

| 캐릭터 | 첫 장면 3종 | 추가 장면 3종 |
|---|---|---|
| 사쿠라 | 측면에서 카드 정리 / 벚꽃길 걷다 돌아보기 / 정원에서 찻잔을 든 안도 | 결의 클로즈업 / 어깨 너머 테이블 / 저녁 데이트 와이드 |
| 아라 | 낮은 카메라의 자신감 / 창가에서 실패 복기 / 칩을 밀어 넣는 3/4 구도 | 당황한 웃음 / 테이블 건너 시선 교환 / 야경 산책 |
| 하나 | 화이트보드 앞 측면 / 독서 후 고개 들기 / 정답 확인 후 미소 | 생각에 잠긴 클로즈업 / 어깨 너머 분석 / 카페 대화 |
| 클로이 | 스트리밍 종료 후 안도 / 하이파이브 / 소파에서 웃는 전신 | 카메라 밖을 보는 집중 / 승리 후 놀람 / 루프탑 파티 |
| 비비안 | 무대 뒤 거울의 측면 / 가면을 손에 든 3/4 / 커튼 옆 실루엣 | 메이크업 소품 정리 / 장갑을 고쳐 끼는 동작 / 드레스 무도회 |
| 엘레나 | 눈 내리는 창밖 / 찻잔을 든 측면 / 코트를 걸치며 돌아보기 | 분석적인 시선 / 작은 미소 클로즈업 / 야간 정원 대화 |

각 장면 4후보 = 144장. 전체 양산 전에 서로 다른 외형의 캐릭터 2명 × 6장면 × 2후보 = 24장으로 동일 인물 유지와 각도 변화부터 평가한다. 파일럿 후보는 최종 144장에 재사용할 수 있다.

승인된 36장을 단순히 한꺼번에 게임에 넣지 않는다. 실제 연결할 스토리·인연·로비 장면 키를 지정해 6~12장씩 공개한다. 우선 영상화는 장면 변화가 큰 승인작 12장, 나머지는 정지 CG로 먼저 사용할 수 있다. 4.4초 루프 외에 1회 등장 연출과 2~3컷 씬 구성도 후속 UI 범위로 분리한다.

## 5. 지속 제작 워커

워크스페이스는 `D:/AI-Image-Video/output/poker-doku-library/`로 분리한다. 게임 저장소의 `public/`에는 승인·선별·인코딩이 끝난 파일만 반영한다.

```text
장면 목록/참조 → 영속 작업 대기열 → GPU 워커 1개 → 후보 이미지
                                               ↓
                        다음 후보 생성 ← 자동 파일 검사/컨택트 시트
                                               ↓
                              사람의 채택/보류/재생성 판정
                                               ↓
                            선별 이미지 → H3 → 6프레임 검수
                                               ↓
                          웹 인코딩 → 게임 매니페스트 → 배포
```

- **작업 원장**: SQLite에 job ID, 캐릭터, 장면, 각도, 표정, 참조 파일 hash, seed, 모델/노드 버전, 워크플로 hash, 상태, 제출 prompt ID, 재시도 횟수, 결과 경로, 소요 시간을 기록한다.
- **상태**: planned → submitted → running → generated → review → approved/rejected. 영상 작업은 승인 이미지 ID를 부모로 가진 별도 행이다. 사용자 검수 상태와 GPU 실행 상태를 섞지 않는다.
- **중단 복구**: 제출 후 반환된 prompt ID를 먼저 저장한다. 재시작 시 `/queue`와 `/history/{prompt_id}`를 조회해 기존 작업을 회수한다. 제출 응답만 유실된 작업은 client/job 식별자와 출력 파일로 대조하고, 확인 없이 중복 생성하지 않는다.
- **연속 실행**: 승인된 장면 목록의 미실행 후보를 계속 처리한다. 목록이 소진되면 idle로 대기하고 신규 장면을 받아 재개한다. 내용 없는 무한 랜덤 생성 대신, 사용 가능한 후보 재고를 채우는 방식이다.
- **VRAM 관리**: 이미지와 H3를 동시에 돌리지 않는다. 이미지 묶음→승인 영상 묶음 순으로 모델 교체를 줄인다. GPU를 쓰는 다른 작업이 감지되면 신규 제출을 보류한다.
- **오류**: 실패 작업은 최대 2회 재시도 후 보류하고 다음 작업으로 이동한다. 연속 3회 장치 오류, 출력 드라이브 여유 30GB 미만, 사용자가 설정한 GPU 온도/VRAM 한계 초과 시 pause한다. 스스로 다른 앱을 종료하지 않는다.
- **제어**: status, pause-after-current, resume, stop-after-current를 제공한다. 사용자가 PC를 쓸 때 즉시 신규 제출을 멈출 수 있다. Windows 시작 시 실행은 별도 opt-in으로 둔다.
- **검수 대기 중에도** 승인된 장면 목록에 다른 작업이 있으면 다음 후보를 만든다. 검수 보류작을 자동으로 배포하지 않는다.

ComfyUI는 `/prompt` 제출, `/queue` 상태, `/history` 결과, WebSocket 진행 이벤트를 제공한다. 이것을 영속 워커의 실행 포트로 사용한다. [공식 API 경로](https://docs.comfy.org/development/comfyui-server/comms_routes)

## 6. 자동 검사와 사람의 검수

자동 검사는 디코딩 성공, 규격, 파일 크기, 중복/유사 이미지 후보, 참조·모델 이력 유무까지 담당한다. 얼굴 동일성·손·소품·서사 적합성은 컨택트 시트로 사람이 판정한다. 얼굴 유사도 점수 하나로 정면 이미지만 살아남게 만들지 않는다.

검수 화면은 캐릭터·장면·각도·표정 필터와 승인/재생성/보류를 제공한다. 재생성은 이유(얼굴/손/시선/각도/의상/유사함)를 저장해 같은 오류의 재생산을 줄인다. 영상은 첫·중간·끝 6프레임과 실제 루프를 확인한다.

초기 측정은 시간당 후보 수, 후보 대비 채택률, 승인작당 비용 대신 **GPU 시간**, 최근 공개작 중 새 구도 비중으로 한다. 생성 장수만 목표로 삼지 않는다. 원본 PNG와 작업 JSON은 로컬 보관, 게임은 WebP·WebM/MP4로 내보낸다.

## 7. 성인 대상 보너스 CG 기획

이번 제안 범위는 **명백한 성인 캐릭터의 비노골적 로맨스와 화보**다. 노출 정도를 끝없이 높이는 방식보다 캐릭터와의 관계 변화·둘만의 장면·의상과 조명을 보너스의 차별점으로 삼는다.

- 장면군 A: 드레스 무도회, 옥상 야경, 수영복 리조트 화보처럼 캐릭터마다 다른 분위기의 특별 의상 씬.
- 장면군 B: 데이트 후 포옹, 손잡기, 가벼운 키스처럼 관계가 진전되는 장면. 구체적인 성행위 묘사는 포함하지 않는다.
- 장면군 C: 무대 뒤 비비안, 눈 오는 창가의 엘레나 등 공개 테이블에서 볼 수 없는 사적인 표정과 대화.
- 초기 구성: 6명 × 2장면 × 4후보 = 48후보에서 12장 선별. 메인 144후보 파일럿이 통과한 후 같은 제작 워커에 별도 큐로 추가한다.
- 마스코트·동물 캐릭터는 이 보너스 라인업에서 제외한다. 성인 인간 캐릭터의 기존 나이·외형·성격을 유지한다.
- 해금은 인연 에피소드 완료에 연결한다. 포커 승패·큰 베팅·손실 회복에 보너스를 연동하지 않고, 게임 능력치도 주지 않는다. 장면별 영수증으로 중복 지급을 막는다.
- 일반 CG와 구분되는 갤러리 필터 및 사용자 표시 설정을 설계한다. 이 설정은 노출 선호 기능이며 연령 인증을 대신하지 않는다.
- 원본·미검수 후보는 공개 웹 경로에 넣지 않는다. 접근 제한이 필요한 최종 자산은 공개 `public/` URL 대신 서버 권한 확인 후 제공하는 별도 설계가 필요하다. 서버의 자격 판정과 화면의 표시 토글을 분리한다.

로컬 제작 여부와 서비스의 등급/인증 절차는 별개의 사항이다. 등급 확정이나 인증 의무에 대한 법적 판단은 이 문서에서 내리지 않는다. 출시 콘텐츠 범위가 확정되면 기존 `deploy/README.md` 출시 확인 절차와 맞춘다.

## 8. 실행 순서와 산출물

1. `scripts/art/poker-doku-library.md`: 캐릭터 정본·금지된 중복 구도·검수 기준을 제작 규약으로 고정한다.
2. `scripts/art/workflows/poker-doku-sdxl.json`: 기존 워크플로를 복제해 24후보 파일럿을 생성하고, 참조/포즈 강도와 출력 규격을 비교한다. 합격 기준은 각 캐릭터의 6장면 중 최소 4장면에서 동일 인물이며 계획한 방향·동작이 보이는 후보 1개 이상이다.
3. `scripts/art/library-worker.py`와 `scripts/art/library-manifest.json`: 위 작업 원장·재시작·pause/resume를 구현한다. 재시작 뒤 완료 파일 중복 생성 0건, 실패 건 격리, 다른 GPU 작업과 동시 실행 방지가 수용 기준이다.
4. `scripts/art/library-review.py`: 컨택트 시트와 로컬 검수 페이지를 만들고, 승인작만 export 목록에 기록한다.
5. 승인작 12개에 현재 `story-video-h3.py`와 인코더를 연결한다. 새 영상별 프레임 시트·실재생·모바일 크롭 검수를 수행한다.
6. `story-cgs.ts`, `story-video.ts`, 실제 씬 데이터 또는 인연 씬 키에 연결한다. 성인 대상 보너스 라인은 별도 보상/표시/자산 접근 설계를 검토한 뒤 연결한다.
