## 환경

- Next 커스텀 서버 localhost:3011, 실제 Socket.io·PokerEngine·StoryRunCoordinator·LiveTableAdapter.
- Windows Chrome headless, Playwright CDP. 모바일 뷰포트 390×844 / 데스크톱 1280×900. 실제 휴대전화·음성 출력 검증은 아니다.
- 통합 커밋 `25738a9`. 서버 프로세스는 코드 병합 뒤 재시작했다. 병합 중 Next HMR이 클라이언트 스토어를 초기화한 상태는 정상 재접속의 검증 근거로 사용하지 않았다.
- QA 원본 화면/스크립트는 git 제외 `qa-tmp/expansion-live/`. 복구 문구·쿠키·인증 토큰을 보고서에 남기지 않는다.

## 확인한 흐름

1. Ch3: 도입·드릴·프리셋은 운영자 스킵으로 실제 스파링에 진입했다. 미션 전체보기는 실제 서버 미션/진행도를 표시했다.
2. 모바일 미션 모달을 열어 둔 동안 90초 턴 만료→자동 폴드→수련 hold를 확인했다. 모달은 유지됐고, [테이블로 돌아가기]→[계속하기] 뒤 다음 핸드가 시작됐다. 전체 문구·진행도 읽기 가능.
3. 데스크톱 동일 모달의 전체 문구/닫기/중앙 배치 확인. 화면: `mission-live-mobile-open.png`, `mission-live-desktop-open.png`.
4. Ch6: 앞 씬·레슨·드릴·프리셋은 운영자 스킵. 스파링은 실제 버튼으로 진행해 결산/보상 화면까지 도달했다. 전체 정규 수업을 직접 풀어 완주한 검증은 아니다.
5. Ch6 결산에서 도장 Lv.3→5, 비선택 담당 아라 인연 Lv.1→3, 보상 CG/아이템 리빌, 일반 레벨 보상 알림 `새 아이템: 벚꽃`, [허브로] 복귀와 완료 기록을 확인했다. 결산 UI는 칩 +800을 표시했고 DB에도 정상 지급됐다. 잔액 표시 갱신 문제는 아래에 별도 기록한다.
6. 결산 컷신은 안내 문구를 탭해 닫고 리빌을 마친 후 CTA가 표시됐다. 화면: `r1-ch6-success-mobile.png`, `r1-ch6-reward-overlay.png`.

7. Ch6 두 번째 스파링은 실제 UI로 콜/체크를 반복해 파산시켰다. 실패 씬에 진입했고 새로고침 후 같은 실패 씬으로 복원됐다. [결산 보기]는 보상 0·기존 드릴 7문 결과를 표시했다. 실패 결산에서도 다시 새로고침하여 결과와 재도전 CTA가 복원됐다.
8. [스파링만 재도전]은 씬/레슨/드릴 없이 새 방의 Ch6 스파링으로 바로 들어갔다. 착석 순간 히어로·팽팽 모두 1,000칩, 0핸드였으며 첫 블라인드 이후 990/980으로 정상 진행됐다. `r1-ch6-failure-scene-mobile.png`, `r1-ch6-failure-result-mobile.png`, `r1-ch6-retry-buttons-mobile.png`, `r1-ch6-retry-fresh-mobile.png`.

## 점검 중 발견한 작은 문구 불일치

- `FirstTableGuide`의 일반 지갑 설명이 스토리 연습 방에서도 나온다. 실제 테이블 상단은 지갑 무관으로 올바르게 안내한다. 스토리/연습 경제에 맞는 안내로 바꿀 대상이다.
- Ch3/Ch6의 `net-chips minBB:0` 보너스는 시작 스택 유지 판정인데 각각 드라코/팽팽보다 많은 칩이라고 표기된다. 목표 로직에 맞춰 문구를 고칠 대상이다.
- Ch6 파산 실패 씬이 실제로 발생하지 않은 하위 핸드 3벳 콜을 단정했다. 실패 원인을 단정하지 않는 대사로 바꿀 대상이다.
- 첫 완료·S의 +800칩은 DB `wallets.balance=10800`, `STORY_REWARD` 원장 +500/+300으로 정상 지급됐다. 화면은 10000을 유지하다 다음 방 복귀 때 10800으로 바뀌었다. `page.tsx`의 방 이탈 refresh가 보상 지급 전 실행되는 시점 문제다.
- 이미 Ch6 첫 완주/S 보상을 받은 프로필이 이후 실패하면 해당 CG 3개가 '다음 보상'에 잠금 표시됐다. 실패 결과에서 readonly 보유 조회를 사용해 미획득 항목만 표시하도록 고칠 대상이다.

위 5종 관찰 사항은 R1c 담당 Astra Medium에게 재현 근거와 함께 배정했다. 작은 문구 변경은 별도 테스트를 만들지 않고 동작 변경은 관련 회귀를 추가한다.

## R1c 통합 후 확인

`4edbe30`을 통합한 뒤 서버를 재시작했다. Ch1을 운영자 스킵으로 결산 직전까지 보내 **보상 시점만** 검증했다. 결산 전 10,800칩 → 결산 응답 직후 UI 11,600칩, DB 11,600칩으로 일치했다. 방 재입장·이탈이나 페이지 새로고침 없이 최신 잔액이 표시됐다. 원장의 새 행은 Ch1 첫 완주 +500, S +300이며, 이전 Ch6 지급과 분리되어 있다. 이 절차는 정규 Ch1 수업 전체 플레이 검증이 아니다.

스크린샷 `r1c-wallet-updated-mobile.png`에서 모바일 허브 카드의 기존 우측 넘침을 추가 발견했다. 390px viewport에서 카드 오른쪽 경계가 419.56px였다. 모바일 grid를 명시적으로 1열(minmax(0,1fr))로 설정하고 카드에 min-w-0를 적용한 뒤 390px에서 right=361px, 320px에서 right=291px, desktop 1280px에서 2열 right=634/1057px로 모두 화면 내부에 들어왔다. `r1c-hub-fixed-390.png` 확대본에서 시작/실력확인/다시 버튼이 완전히 보이는 것을 확인했다.

기존 CG를 다시 잠근 실패 미리보기·실패 씬 포기 버튼·목표 문구·가이드 문구는 구현/회귀 검사로 보정했다. 실제 휴대전화 터치와 음성/BGM은 이번 headless 브라우저 검사 대상이 아니며, 모든 정규 수업을 직접 풀었다고 주장하지 않는다.
