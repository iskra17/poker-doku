# 기록실 이벤트 CG 재작업

## 원인과 결정

기존 사쿠라 CG 네 장은 GPT Image 2 원화와 로컬 H3 영상의 조합이었다. 원본 PNG의 C2PA(gpt-image 2.0), 당시 image_gen 호출과 WebP 변환 결과로 확인했다. 이후 추가한 사쿠라·엘레나 여덟 장은 Qwen-Image-Edit 2511 INT8 ConvRot + Lightning 4-step, 캐릭터 showcase 한 장만 참조하는 다른 경로였다. 기존 CG의 렌더링을 스타일 기준으로 주지 않았고, 여덟 장 중 여섯 장에는 영상도 없었다. 양자화나 스텝 수 하나만 원인이라고 단정할 수는 없다.

Claude Fable 5.1이 실제 구작/신작 비교 시트를 검토했다. 주요 의견은 인물에 연결되는 조명, 머리카락·옷 질감, 공간 깊이, 행동과 시선의 목적이 약해졌다는 것이다. Astra는 기존 제작 경로로 원화를 재작업하고 스타일 참조와 인물 참조를 분리하기로 결정했다. Fable의 전체 최종 검토는 `../reviews/2026-09-05-event-cg-quality-fable.md`에 있다. 추가 전체 코드 리뷰는 요청하지 않았다.

## 범위

사쿠라: 책과 벚꽃길, 작은 승리, 빗소리와 기다림, 책장에서 꺼낸 질문.
엘레나: 그림자 읽기, 강변의 생각, 창밖의 흰 여백, 칩 앞의 침묵.

새 원화는 GPT Image 2 1024×1536 → WebP 품질90, 768×1152. 모든 원본 PNG에서 모델 메타데이터를 확인했다. 사쿠라는 기존 프롤로그/에필로그를 화풍 기준, showcase를 인물 기준으로 사용했다. 엘레나는 기존 scene-lv5의 렌더링과 showcase의 인물/의상을 각각 참조했다. 원화 생성은 내장 imagegen, 영상 생성은 사용자 로컬 RTX 5090/ComfyUI H3다.

여덟 장 모두 같은 새 원화를 부모로 하는 무음 루프를 연결한다. 최종 WebP를 PNG로 디코드한 바이트를 영상 시작·끝 참조로 사용하며, 외부 원화는 Comfy 생성 이력을 꾸미지 않고 `import-external-image`의 외부 출처 영수증으로 기록한다. 원본/변환/참조/프롬프트/SHA는 `scripts/art/library/recipes/event-cg-v2-20260905/`에 있다. 이미지 생성 시도 수는 해당 로컬 원장에서 0이다.

새 파일은 `scene-<id>-v2.webp/.mp4/.webm`. 기존 CG와 49개 원래 영상, 이전 공급 파일은 보존한다. 보상 ID `story-cg-act3-luna-analysis`와 `story-cg-act3-elena-snow`도 같은 새 씬 원화/영상으로 연결하며, 지급 ID·해금·진행 기록은 바꾸지 않는다.

## 시각 검수

정지 이미지는 구 CG와 비교해 얼굴·의상·손, 세밀한 선/질감, 따뜻한 광원과 차가운 그림자, 전경/중경/원경, 장면별 시선·행동을 검수했다. 영상은 12개 시간대 프레임과 원해상도 중간 프레임을 직접 확인하며 전체 디코딩과 첫/끝 연결도 검사한다.

벚꽃길 첫 영상은 전신 구도에서 얼굴로 크게 확대했다가 돌아오는 움직임 때문에 거절했다. 같은 승인 원화를 유지하고 고정 전신 구도를 강조하는 로컬 H3 재시도 한 개를 별도 manifest로 기록했다. 다른 장면은 눈 깜빡임, 머리카락, 비/눈/수면 등의 작은 움직임을 사용한다. 서재의 책 페이지 움직임은 형태가 자연스럽게 유지되어 허용했다. 프롬프트의 모든 고정 지시가 모델에서 엄밀하게 지켜졌다고 주장하지 않는다.

## 검증 및 배포 상태

원화8/영상8쌍의 공급 해시와 보상 연결 테스트22개, 타입 검사와 변경 파일 린트가 통과했다. 브라우저18케이스(CgStage8, ScenePlayer8, RewardCutscene2)는 반복 재생·모션 감소·WebM 실패→MP4·모든 영상 실패→정지 CG·실패 뒤 다시 열기를 통과했고, 108개 폭/상태 검사와 24파일 전후 해시 검사도 통과했다. 첫 UI 런의 실패는 QA 스크립트의 한글 선택자 인코딩 문제였으며 제품 오류와 구분해 보관했다.

화면을 직접 확인하다 CgStage의 기존 표시 결함도 발견했다. 정지 이미지만 최대 높이/폭 제한을 받고 영상은 원해상도768×1152로 펼쳐져, PC에서 부모770×762에 아래쪽이 잘렸다. 영상에도 정지 이미지와 같은 최대 크기(66dvh/620px, 88vw/420px)를 적용했다. ScenePlayer의 처음 넓은 캡처는 QA fixture 차이였으며 실제 StoryStage와 같은448px 폭으로 재확인했다.

표시 수정 후 CgStage 씬8+보상2의 모바일/PC 전체2:3 비율과 부모 잘림 없음 재검증을 통과했다. 영상 실측은390px 화면에서343.1875×514.78125,1280px 화면에서396×594였다. 대표2개 루프/모션감소/MP4대체/정지fallback/재열기도 다시 통과했다. 첫 크기 검사 시 정지fallback의 기존 breathing zoom까지 엄격한 영상 치수와 비교한 QA 오류는 별도 보관하고, 애니메이션 상태에 맞게 측정을 분리했다. 실제 영상과 모션감소 이미지의 비율/크기 검사는 완화하지 않았다.

UI 증빙: `qa-tmp/expansion-reviews/cg-v2-ui-2026-09-05T01-33-23-131Z/`, `cg-v2-ui-sizing-2026-09-05T01-39-24-268Z/`. 테스트용 route/브라우저/Next 서버를 정리했고, GPU 큐와 생성 작업도 종료했다. 로컬 ComfyUI 서비스는 기존 실행 상태로 보존했다. 최종 영상은106프레임/24fps,768×1152, H.264/VP9 쌍이며16파일 합계9,193,070바이트(모두파일당2.5MB미만). 실제 H3 시도9개 중 확대·축소가 있던1개만 거절했다.
