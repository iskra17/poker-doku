# 다음 세션 핸드오프 — Fable 5.1 총괄 / Ch10~12

2026-09-06 사용자 결정. 이번 작업은 인계와 역할 변경만 수행한다. R4 구현을 지금 시작하지 않는다.

## 역할과 최종 판단

| 역할 | 모델 | 책임 |
|---|---|---|
| 오케스트레이션·최종 판단 | Claude Fable 5.1 | 우선순위, 작업 분해, 의존성/파일 소유권, 리뷰 채택 여부, 통합과 완료 보고 |
| 기획 검토·코드 리뷰·심층 테스트 | GPT 6 Astra | 기존 Fable 역할을 인계. 미해결 계약, 실패/재접속/정산/중복 보상 경계를 독립 검토하고 재현 근거 제시 |
| 구현 서브에이전트 | Claude Opus | 확정된 범위의 코드·챕터 데이터·관련 테스트·수정 커밋, 검증 결과 보고 |

흐름: Fable 계획 → 필요한 경계만 Astra 검토 → Fable 확정 → Opus 구현 → 필요한 변경만 Astra 리뷰 → Fable 최종 판단·통합. 리뷰 결과를 구현자에게 바로 전부 적용시키지 않고 Fable이 근거와 범위를 판단한다. 기존 Astra 총괄/Fable 리뷰/Astra Low·Medium 구현 배정은 이 결정으로 대체한다.

다음 세션의 실제 주 모델을 Fable 5.1로 선택한 뒤 시작한다. 이 문서 변경 자체가 현재 앱의 모델 선택을 바꾸지는 않는다. 호출 결과의 실제 모델 식별자와 추론 노력을 기록한다. Opus 버전은 설치된 실제 버전을 확인해 기록하며 임의 버전을 가정하지 않는다. 지정 모델을 호출할 수 없다면 제약을 알리고, 다른 모델을 해당 모델인 것처럼 표시하지 않는다.

## 다음 구현 순서

1. **R4a 드릴**: MDF와 SnG 문항을 기존 생성기·해설·공개 DTO·복습 계약에 추가한다. MDF=P/(P+B)와 콜 필요 승률=B/(P+2B)를 구분한다. 첫 Opus 작업은 이 범위로 한정하고 관련 테스트를 함께 맡긴다.
2. **R4b Ch10·11**: 확정된 레슨·드릴·프리셋·스파링·실패/보상 연결. Ch10 두 번째 HU 실패 시 해당 HU만 재도전. Ch11은30핸드/any-k(3)와 실제 오픈·c벳·밸류 기회 중1회 실행 조건을 함께 적용한다. 기회0이나 전부 프리플랍 폴드가 실행 조건을 통과하지 않게 한다.
3. **R4c Ch12 졸업**: 실제6인 practice SnG,1,000칩/2분 구조. 일반 SnG1,500칩/3분은 유지한다. 실제 순위로 종료하고, 부재 중에도 블라인드와 자동 액션을 진행한다. 일반 수련 cash의 hold/파산 리필·일반 SnG XP 중복 지급 경로를 재사용하지 않는다.
4. **졸업 영속과 재도전**: 실제 순위 receipt/ITM/우승 자격과 최초 완료·보상을 정해진 트랜잭션 경계에서 확정한다. 졸업 대결만 재도전은 durable Ch12 완료 자격으로 진입하며 새1,000칩·드릴null·XP/인연/칩0. 검은띠는 전체4막 완료와 ITM 자격의 교집합, Ch12 exam은 UI/서버 모두 거절한다.

Astra 검토는 새로 남은 문제에 한정한다. 우선 검토 대상은 Ch12 순위 확정/정산·재접속·중복 지급·졸업 대결만 재도전 경계다. R4a는 구현에 필요한 가정이 확정 설계에 없을 때 그 쟁점만 검토한다. 기존 설계를 다시 통째로 리뷰시키지 않는다.

## 비용·검증·작업 경계

- 총괄 외 동시 작업자 최대2명(CLI 포함), GPU 워커1개. Opus별 worktree와 파일 소유권을 분리한다. 공유 DTO/목표/마이그레이션은 담당자 한 명이 먼저 확정한다. 이미 배포한 아트 브랜치를 새 구현 기준으로 쓰지 않는다.
- 작업자에게 필요한 파일·계약·완료 조건만 전달한다. 전체 저장소 감사나 완료된 모델 리뷰를 반복하지 않는다. 모델 교체 자체를 이유로 검증을 처음부터 다시 시작하지 않는다.
- 구현자는 관련 테스트만 `--maxWorkers=2`. Fable은 의미 있는 통합 배치당 전체 Vitest `--maxWorkers=4`1회와 build/lint/tsc를 수행한다. 변경·실패·미해결 위험이 없으면 같은 검사를 반복하지 않는다.
- 브라우저는 Ch10 HU 재도전, Ch11 실행 확인, Ch12 실제 순위/재접속/졸업 대결만 재도전에 집중한다. 운영자 스킵/합성 DTO 화면/실제 플레이의 검증 범위를 구분한다. 운영 데이터에 QA 진행을 기록하지 않는다.
- DB는 재개 시 최신 버전을 확인해 다음 번호를 쓴다. 적용된 v34~v36을 수정하지 않는다. 없는 CG/의상을 AVAILABLE에 등록하지 않는다.
- 후속 아트는 Ch8 S 전용 CG가 남아 있다. 랜덤 리딩/체크레이즈 기회 빈도·체감 길이는 실제 평균 측정이 남아 있다. 이것을 새 전체 감사나 R4 선행 대규모 아트 양산으로 확대하지 않는다.
- 하드 모드·추가 의상·MTT 공개 재개·멀티테이블·신규 계정 연동은 이번 R4 필수 범위가 아니다. 다음 세션은 새 배포 지시가 없다면 구현·검증·인계까지 하고 운영 배포하지 않는다.
