## 2. 단계와 병렬도

| 단계 | 도구 | 병렬 | 소요(실측 전 추정) |
|---|---|---|---|

| ③ 재생성 | 반려 장면만 프롬프트 보정 후 개별 재실행(`run-wave.sh … <id>` + 계획 JSON 수정) | 반려 수만큼 | — |

## 3. 검수 규칙

- 승인 단위는 장면 1장(캐릭터당 5장). 원본 PNG 전체 해상도로 얼굴 동일성·손·의상 정합·서사 적합·콘텐츠 경계를 본다. 시트는 비교용이다.
- 반려 사유를 계획 JSON `notes`에 남기고(얼굴/손/시선/각도/의상/유사함/경계), 같은 오류가 반복되면 프롬프트 규칙을 공통부에 올린다.
- 영상은 첫/끝 프레임 동일, 카메라 고정(줌/팬 거절 — v2 벚꽃길 선례), 얼굴·의상 유지, 미세 앰비언트 모션만.

## 4. 게임 연결 계약 (다음 Opus 배치 — R4c 뒤)

- **자산**: `public/assets/story/cg/bonus-<character>-<scene>.webp` + `public/assets/story/video/bonus-<character>-<scene>.{mp4,webm}`.
  현재 라인은 비노골적이므로 다른 CG와 같은 공개 경로를 쓴다(제작 기획 §7의 "서버 권한 확인 후 제공"은 더 높은 등급의 자산에만 적용 — 등급 상향 시 별도 설계).
- **매니페스트**: 새 `src/lib/assets/bonus-cgs.ts`(id·캐릭터·장면·제목·캡션·아트 경로) + `story-video.ts VIDEO_AVAILABLE`에 `bonus-*` 등록(영상 쌍이 실재하는 id만).
- **해금**: 캐릭터별 인연 레벨 임계 — 장면 순서대로 Lv 5/10/15/20/25(히로인 6명), 인연이 없는 미야코·유즈키·린·잉그리드는 **도장 레벨** 임계
  10/20/30/40/50(제작 기획 §7 "인연 에피소드 완료에 연결, 승패·베팅 연동 금지, 능력치 없음"). 자격은 durable 상태에서 파생하고 영수증
  (`story_rewards` 카탈로그 확장 또는 별도 `bonus_cg_unlocks`)으로 중복을 막는다 — 정확한 테이블은 배치 시 결정.
- **표시**: 기록실(`GalleryModal`)에 '보너스' 필터 탭 + 설정에 「보너스 CG 표시」 토글(기본 켜짐, 로컬 설정 — 노출 선호 기능이며 연령 인증이 아님).
  운영자 모드는 기존 `unlockAll` 미리보기 규칙 그대로.
- **회귀**: 매니페스트 패리티(파일 존재·영상 쌍), 해금 판정 순수 함수, 영수증 멱등, 기록실 필터/토글.
