# A2 영속 제작 큐 구현 계획

**승인 근거:** control commit `23f8d57`의 `2026-09-05-art-queue-design.md`, 실제 Fable xhigh 검토 반영판. 이 계획은 추가 에이전트 없이 직접 실행한다.
**목표:** 실제 GPU를 사용하지 않고 fake Comfy와 파일 검증으로 운영 가능한 단일 제작 큐/승인/export 기반을 완성한다. 실제 GPU smoke와 승인 CG 8장 공급은 별도 단계다.
**구조:** Python stdlib SQLite + OS lock + urllib Comfy adapter, Pillow 이미지 검사/시트, ffprobe 영상 검사, 기존 Node convert.mjs 기반 CG 변환. 짧은 트랜잭션과 불변 제출 intent를 분리한다.

1. `library/common.py`, `store.py`: 고정 전역 GPU OS lock, 정규화 경로/해시, 원장/설정. 다른 DB root와 endpoint별칭도 같은 lock. pause 명령은 워커 lock 없이 DB 설정만 변경.
2. `recipe.py`, `comfy.py`, `media.py`: 해시가 포함된 recipe 바인딩, 안전한 입력 staging, queue/history 실제 tuple slot3 extra_data 해석, PNG metadata 및 영상 ffprobe/프레임 검증. 승인 전 recipe는 import 거절.
3. `worker.py`: submitting intent 선커밋→요청→submitted→파일검증→generated. unknown은 자동 재제출 없이 격리하고 빈 큐일 때 다른 pending 진행. 재시작은 queue/history/PNG로 조정. failed retry는 명시 명령과 최대 attempt 제한.
4. `review.py`: 확대 링크/contact sheet/HTML, 결과hash에 결속한 승인, 입력변조 검사, 고정 target root 안에서만 신규파일 export. 변환파일 사전기록으로 crash 후 멱등 회수, 기존파일충돌 거절.
5. `cli.py`, `library-worker.py`: init/import/status/run(--watch/--limit)/pause/resume/reconcile(--mark-failed/--retry)/review/sheet/export. 실제 Comfy interrupt/queue변경은 구현하지 않는다.
6. `library/tests/`: 프로세스 경계 fake HTTP Comfy, 실제 OS lock, subprocess killpoint(테스트 전용 주입)으로 제출전/응답유실/결과기록전 중단 복구. 변조/손상/중복/unknown/pause/외부큐/미승인export/다른worktree/충돌 검증.
7. 품질 검수 전인 A1c용 binding recipe는 `queue_approved=false` 예제로만 보존. 기존 단발 runner/output/manifest 수정 없음. 영상 recipe와 승인 이미지 parent 계약도 같은 큐에 포함.
8. 관련 unittest/compile 및 CLI help 검증, 변경파일 한정 커밋. 운영 명령·미실행 GPU smoke 절차를 인계한다.

모델 검증은 제출 전 실제 파일 hash를 읽지만 테스트는 작은 임시 fixture만 사용한다. 전역 lock 경로는 CLI 옵션으로 우회할 수 없고 테스트만 임시 lock dependency를 주입한다. 테스트의 승인 및 export는 임시 DB/임시 target만 사용한다.
