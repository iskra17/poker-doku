# 이벤트 CG 8장 품질 재작업

사용자가 기존 사쿠라4CG 수준을 기준으로 새 사쿠라4/엘레나4CG를 재작업하라고 요청했다. Fable 실제 시각 검토 뒤 Astra가 아래 경로로 확정했다. 게임 기능 확장이나 추가 로컬 모델 실험은 이번 범위가 아니다.

## 확인한 원인

기존 사쿠라4장은 원본 PNG C2PA의 gpt-image 2.0/OpenAI Media Service API와 프로젝트 image_gen 호출 기록, 원본→현재WebP 바이트 일치로 GPT Image2 제작을 확인했다. `poker-doku-art/story-rewards/prompts/common.txt`, `cg-a.txt`, `cg-d.txt`와 2026-09-04 climax 설계/실제 호출이 근거다. 기존 climax는 showcase+neutral뿐 아니라 기존 prologue CG를 세 번째 참조로 썼다.

신규8장은 Qwen Image Edit2511 INT8/Lightning4step, showcase RGB1장, 832×1248 생성→768×1152 변환이다. 기존은1024×1536→768×1152. 서로 다른 모델·참조·스타일 지시가 함께 변경됐으므로 양자화/스텝만 원인이라고 단정하지 않는다. 새 그림의 굵은 선·단순 조명·평면 배경과 기존 그림의 재질·광원·깊이 차이를 실제 비교했다. 또 기존 사쿠라4장은 영상이 있으나 신규8장 중6장은 정지 이미지다. 영상2개는 기존과 같은 H3이며, 영상 모델 변경이 원인은 아니다.

## 확정 경로

1. 내장 imagegen을 사용해8장 원화 재생성. 기존 좋은 CG는 화풍/조명/재질 참조, showcase는 인물/의상 참조로 구분한다. 사쿠라22세/엘레나27세의 일반 수련·일상 장면이며 기존 의상을 유지한다.
2. 먼저 사쿠라 library와 엘레나 lesson을 제작해 인물 정체성·기존CG 렌더링 수준을 실제 시각 비교한다. 통과 후 나머지6장을 같은 기준으로 제작한다. 얇은 선, 머리카락과 옷의 재질, 따뜻한/차가운 광원 대비, 전경/중경/원경, 목적 있는 시선·손동작을 요구한다. 모든 장면을 같은 정면/표정으로 만들지 않는다.
3. 새8개 모두 기존 로컬 H3 first/last-frame 워크플로우로106frame/24fps/768×1152 무음 루프를 제작한다. 정지 원화가 바뀌므로 기존 victory/river 영상도 새로 만든다. 고정카메라·작은 머리카락/비/눈/먼지/수면 움직임 위주. Fable 제안의 칩 굴림·손가락 톡톡은 소품/손 변형 위험이 있어 이번 루프에는 넣지 않는다.
4. 원본/생성출처/프롬프트/해시/시각 판정을 기록하고 `scene-<id>-v2.webp/.mp4/.webm`으로 새 파일을 게시한다. 이전 파일과 첫 공급 원장은 보존한다. 검수 미완료 파일로 availability를 켜지 않는다.
5. 같은 CG를 쓰는 Ch9 보상(analysis/snow)도 v2원화/영상으로 연결한다. 챕터·해금·보상 ID/경제/DB는 변경하지 않는다. 기존49영상/18씬CG는 유지한다.

## 품질 판정과 검증

기존 동일 캐릭터 CG와 나란히 비교해 정체성·의상, 광원의 인물 반영, 공간 깊이, 손/시선의 목적을 확인한다. Fable의 ‘배경 어디에도 평면 영역 없음’은 절대 규칙으로 쓰지 않고, 전체 렌더링 깊이와 초점의 균형으로 판단한다. 영상은 전프레임 디코드와 시간대별 확대 시각검수, 얼굴/의상/손/소품 연속성·끝점 이음새를 확인한다. 원화와 영상이 같은 버전인지 해시로 확인한다.

관련 자산/갤러리/보상 회귀만 실행하고, 변경된 브라우저 표시·실제 영상 재생·모션 감소/파일실패 폴백을 확인한 뒤 build/lint/tsc를 수행한다. 이전 전체 게임 회귀를 반복하지 않는다. Fable 검토는 이번 시각비교1회(3560출력토큰)이며 추가 전체 코드 리뷰를 하지 않는다.

배포는 이번 재작업 검증 후 사용자에게 결과와 함께 알린다. 현재 운영은v85이며 재작업 파일을 중간에 운영에 섞지 않는다.
