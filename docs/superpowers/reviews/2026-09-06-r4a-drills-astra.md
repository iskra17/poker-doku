# R4a MDF·SnG 드릴 계획 검토 — GPT 6 Astra

> 2026-09-06. 모델 `gpt-6-astra`(codex exec, model_reasoning_effort=high, 읽기 전용 sandbox). 대상: [R4a 계획](../plans/2026-09-06-r4a-mdf-sng-drills-plan.md) 중 확정 설계에 없던 가정 4건. 총괄(Fable 5.1) 판정: **4건 전부 수용** — 반영 내용은 계획 문서 「Astra 검토 반영」 절.

**1. MDF — 판정 = 수정 필요**
- 근거: `potChips=P+B`, `toCallChips=B`는 D-ODDS와 일치합니다. D-BE는 히어로가 아직 벳하기 전이므로 `potChips=P`도 일관됩니다. 계획대로 세 금액을 명시하면 명확합니다.
- 세 공식도 맞습니다. `villainBreakeven`은 **상대 블러프의 손익분기 필요 폴드율**로 표기하세요. [MDF·Alpha 정의](https://blog.gtowizard.com/mdf-alpha/)
- 후보 **13쌍 모두 통과**: 최대 반올림 오차 약 0.444%p, 최소 쌍별 간격 5%p입니다. 네 번째 선택지도 표시 정수 기준으로 모든 기존 값과 ≥4%p면 유일합니다.
- 실제 오류는 단위입니다. [learning.ts:93](C:/code/claude/poker-doku/src/lib/poker/learning.ts:93)의 `requiredEquity`는 0~1입니다. `(100,50)`에서 계획의 `callEquity=25`지만 `computePotOdds(50,150).requiredEquity=0.25`입니다.
- **최소 수정:** 비교 대상을 `.pct` 또는 `100×.requiredEquity`로 변경하고, 선택지에는 “가장 가까운 정수 %”라고 명시하세요.

**2. SnG 스택 구간·M — 판정 = 수정 필요**
- 근거: 10BB·20BB는 입문용 분류 기준으로 수용 가능합니다. 계획의 “자동 액션이 아니다” 설명도 적절하지만, `10~20BB` 표기는 `≤10BB`와 겹칩니다.
- **최소 수정:** `숏스택: 10BB 초과~20BB 이하`로 쓰세요. 경계 리롤은 문항 중복을 피할 뿐 정의의 중복을 고치지는 못합니다.
- M은 앤티가 없어도 유효합니다. `M=stack/(SB+BB)`이므로 100/200에서 1,600칩은 **M=5.33**, 8BB입니다. [M 정의](https://pokercopilot.com/assets/poker_statistics_guide.pdf)
- 다만 “몇 오르빗 버티는가”는 **블라인드·인원 고정, 추가 손익 없음**이라는 근사입니다. 3분마다 상승하는 실제 생존 시간으로 읽히지 않도록 이 조건을 추가하세요.
- 앤티 변형에는 **“기본 게임과 다른 연습 가정: 매 핸드 각자 a칩”**을 명시하세요. `a×players`는 개인 앤티 방식이며 BB 앤티 방식과 다릅니다.

**3. 수기 푸시·폴드 — 판정 = 수정 필요**
- 근거: 저장소 `estimateEquity`, `mulberry32(20260906)`, 각 **100,000회** 계산 결과 A♠7♦는 **33.824%**, 9♠4♦는 **27.6075%**입니다.
- 계획의 콜 확률을 그대로 쓰면 BTN은 `0.88²=0.7744`, 최종 팟 3,300~3,400에서 **EV +123~+131칩**입니다.
- UTG는 `0.85⁵=0.443705`, 최종 팟 3,300~3,500에서 **EV −250~−219칩**입니다. 따라서 **푸시/폴드 정답 방향은 유지**됩니다.
- 두 레인지는 `parseRange`로 정상 파싱됩니다. 다만 각각 **144/1326=10.86%**, **182/1326=13.73%**로, “상위 12%·15%”와 일치하지 않습니다.
- **최소 수정:** “상위” 표기를 제거하고 `c=rangeCombos(range,hero).length/C(50,2)`로 통일하면 각각 **9.88%·14.45%**입니다. 독립 근사하에서도 정답 방향은 같습니다. A7o 기대 에퀴티는 약 34%로 고치세요.
- 단일 콜러 단순화는 명시하면 수용 가능합니다. **상대 간 카드 상관·앞선 폴드의 카드 정보는 무시, 첫 콜러 이후 추가 콜 없음**을 문항 가정에 넣으세요.
- 콜러별 팟은 **BB 3,300 / SB 3,400 / 비블라인드 3,500**입니다. 첫 콜러 확률로 가중해야 단일 `evPush`가 재현됩니다. UTG 상대도 모두 커버하도록 스택을 지정하세요.
- `fold EV=0`은 미납입 BTN/UTG의 현재 결정 기준으로 맞습니다. **폴드와 8BB 올인만 비교**한다고 명시하고, 일반 레이즈와 혼동되지 않게 기존 `'all-in'` 액션을 사용하세요.

**4. 기존 계약 — 판정 = 수정 필요**
- 근거: 신규 11개 ID는 현재 ID와 충돌하지 않습니다. 그러나 [generator.test.ts:181](C:/code/claude/poker-doku/src/lib/story/drills/generator.test.ts:181)은 authored 전체 ID 배열을 정확히 비교하므로 **2개 추가 즉시 실패**합니다.
- **최소 수정:** “기존 단언 불변”에 이 배열의 신규 ID 추가를 예외로 허용하세요. 생성기 `EXPECTED_IDS`는 유지해도 됩니다.
- `변형 수 >3`은 **생성형 9종만** 적용해야 합니다. 수기 2종은 seed가 달라도 상황·문항이 같습니다. R3 테스트의 `correct+1` 오답 검사도 그대로 복사하지 말고 허용 오차 밖 값을 쓰세요.
- 상대 조연 6명 제한은 문제없습니다. 기존 풀 테스트에는 D-TYPE 전용 3명 예외가 있으므로, **신규 문항에만** 엄격한 6명 검사를 적용하세요.
- 공개 DTO·허브 라벨은 호환됩니다. 계산 결과는 `explanation.facts`에만 두고, 공개되는 `note`에는 전제만 두세요. 허브 카테고리 검사는 신규 슬롯을 가진 테스트 챕터로 가능합니다.
- SnG의 `toCallChips`를 계획에 명시하세요. 특히 두 수기 문항은 **팟 300, 콜 200**입니다. 기본값 0이면 “체크 가능”이라는 DTO 의미와 충돌합니다.
- 복습은 `(templateId, seed)`로 재생성하므로 레벨·앤티·인원을 모두 seed에서 결정하면 호환됩니다. 선택한 레벨의 BB를 복습 시 `ctx.bigBlind`로 다시 주입할 필요는 없습니다.
