# UI 정리·첫 경험·보상·아레나 기획 초안

작성일: 2026-09-09. 기준: 로컬 `7e30d6e`와 공개 공식 자료.

상태: 커뮤니티 피드백에 대한 검토안. 앱 코드·운영 설정·보상·배포는 변경하지 않았다. UI는 캐릭터/미연시 감성을 유지하고 정보와 장식을 줄이는 방향을 잠정 전제로 한다. 아래 변경 수치는 실험 후보이며 승인된 경제 정책이 아니다.

## 1. 판단과 조사 범위

피드백의 핵심은 “메뉴 설명이 부족하다”가 아니라 “화면에 무엇이 중요한지 모르겠고 읽기 힘들다”이다. ‘AI slop’이라는 반응을 특정 생성 도구의 문제로 단정하지 않는다. 작은 글씨, 반복 설명, 여러 강조색, 패널 속 패널, 과한 그라디언트처럼 실제로 조정할 수 있는 요소부터 다룬다.

현재 소스에는 10px 메뉴 부제, 9~11px 안내/배지, 상시 노출 성장 정보, 파트너 대사와 초보 안내의 중첩이 확인된다. 디자인 토큰도 ‘미드나잇 사쿠라 네온’을 전제로 한다. 단, 이번 세션의 브라우저 연결이 없어 현재 배포 화면을 직접 렌더링해 평가하지는 못했다. 색상 평가는 소스의 불투명 색값으로 계산했으며 전체 화면 접근성 통과/실패 판정이 아니다.

## 3. UI 접근안과 추천

| 접근 | 장점 | 한계 | 판단 |
|---|---|---|---|
| 현재 화면의 부제·장식부터 줄이기 | 작게 출시하고 즉시 비교하기 쉽다 | 2×2 메뉴와 큰 상단 영역은 남는다 | 첫 배치 |
| 캐릭터 감성을 유지한 로비 재구성 | 주요 행동을 크게 만들고 게임 목록에 공간을 돌려준다 | 화면 구조 변경과 모바일 검증이 필요하다 | 목표 방향 |
| 전체 아트·UI 외주 리디자인 | 일관된 아트 디렉션을 얻을 수 있다 | 메뉴 구조·첫 경험이 불명확하면 외주도 다시 작업한다 | 구조 검증 뒤 판단 |

### 당장 줄일 것

| 현재 | 제안 |
|---|---|
| 일반 게임 / 친구·봇과 자유롭게 | 게임 |
| 수련 스토리 / 그녀와 배우는 기본기 | 스토리 |
| 포커 아레나 / 시즌 공식 경쟁 | 아레나 |
| 수련 과제 / 오늘의 성장 목표 | 과제 |

부제는 네 개 모두 상시 노출에서 제거한다. 설명을 알아야 선택할 수 있는 모드는 최초 진입 시 한 문장만 제공한다. 아이콘만 남기지 않고 이름은 유지한다. 짧은 이름의 이해도가 떨어지면 원래 명칭으로 되돌리되 부제는 되살리지 않는다.

‘수련 과제’는 대전 모드가 아니라 다른 플레이에서 달성하는 목표다. 초기 배치에서는 위치를 유지하고, 다음 배치에서 프로필 옆 ‘과제’ 버튼으로 옮기는 안을 비교한다. 이후 모바일 주 탐색은 게임·스토리·아레나 세 목적지로 정리할 수 있다. 하단 탭과 상단 탭을 동시에 두지 않는다.

목표 로비는 상단의 프로필/지갑, 캐릭터와 짧은 한 줄, 크게 강조된 시작/이어하기 버튼, 선택한 모드의 내용 순서다. 복귀할 좌석이 있으면 ‘게임 복귀’가 최우선이다. 새 사용자에게는 ‘첫 수련 시작’, 기존 사용자에게는 현재 진행 상황에 맞는 행동을 하나만 강조한다.

### 글씨·장식 규칙

- 주요 버튼과 본문은 14~16px, 보조 정보는 원칙적으로 12px 이상을 시안 기준으로 삼는다. 이는 프로젝트 디자인 목표이며 WCAG의 글자 크기 규정으로 부르지 않는다.
- 본문을 줄여 공간을 확보한다. 설명을 남긴 채 글자만 더 작게 만들지 않는다.
- 일반 텍스트의 색상 대비는 4.5:1 이상을 목표로 한다. 일부 작은 배지가 배경과 겹친 실제 상태도 따로 확인한다.
- 현재 `PartnerCard`/`StoryHub` 시작 버튼의 흰색 글자 대 `blossom #ff7eb6`는 2.36:1, 대 `mystic #a78bfa`는 2.72:1이다. 그라디언트 끝점 기준으로도 낮아 더 어두운 버튼색 또는 어두운 글자색이 필요하다.
- 반대로 기본 보조 글자 `ink-dim` 대 불투명 `panel`은 8.69:1이다. 전부 밝게 만드는 방식으로 해결할 문제는 아니다.
- 기본 화면에서는 주 강조색 하나를 선택한다. 금색은 칩/보상처럼 의미가 있을 때만 쓴다. 기존 디자인 토큰을 정리하고 색상 하드코딩을 늘리지 않는다.
- 일러스트 위 설명은 불투명에 가까운 안정된 바탕을 사용한다. 패널마다 색 테두리·광택·그림자를 겹치지 않는다.
- 반복되는 파트너 대사, 초보 안내, 추천 사유를 동시에 띄우지 않는다. 안내 중에는 캐릭터의 안내 한 줄이 해당 공간을 쓴다.
- XP 상세 수치·인연 상세·경기권은 관련 화면으로 옮긴다. 지갑, 복귀 좌석, 수령 가능한 보상과 오류는 상황에 맞춰 유지한다. ‘오늘 무료 칩 받음’ 같은 완료 버튼은 지속적으로 큰 공간을 차지하지 않게 한다.
- 움직임은 버튼 피드백·딜링·실제 획득 등 사건 중심으로 제한한다. 기본 로비의 장식용 반복 점멸은 줄이고 모션 감소 설정을 따른다.
- 테이블은 카드·팟·현재 행동·남은 시간을 우선한다. 최근 피드백으로 펼친 미션과 채팅은 다시 일괄 숨기지 않고 사용자의 접기 선택과 액션 영역 확보 계약을 유지한다.

출처: [W3C 텍스트 대비 기준](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html). 목표 크기의 터치 영역, 320/390/430px 화면, 확대·키보드·모션 감소 상태는 시안 구현 시 별도 확인한다.

## 4. 튜토리얼: 실제 행동과 연결

### 이미 있는 것

- `PartnerCard`에는 첫 수련 버튼의 금색 링과 글 안내가 있다.
- `Coachmarks`는 화면 전체를 덮는 세 장의 설명이며, 탭하면 닫히고 본인 턴이 시작되면 비켜선다.
- Ch1에는 첫 두 드릴 완료의 작은 성취 지점이 이미 추가됐다. 설명을 건너뛰고 문제만 풀어 보상까지 받는 경로도 있다.
- 스토리에는 프리셋 라이브 테이블과 서버의 턴 보류/재개 기반이 있다.

따라서 “인터랙티브 튜토리얼이 전혀 없다”는 판단은 부정확하다. 버튼 강조와 실제 드릴은 있지만 로비→첫 진입→실제 액션을 연속으로 따라가는 위치 기반 안내는 아직 없다.

### 제안 흐름

| 단계 | 보이는 안내 | 다음 단계 조건 |
|---|---|---|
| 첫 진입 | 실제 ‘첫 수련 시작’ 버튼 하나를 강조, “여기서 시작해요.” | 사용자가 누르고 서버가 런 시작을 확인 |
| 첫 문제 | 답을 고를 영역과 제출 버튼을 상황에 맞게 하나씩 강조 | 실제 답변 접수와 결과 수신 |
| 첫 성취 | 기존 두 문제 완료 장면을 짧게 보여주고 이어하기 제공 | 사용자가 계속 선택 |
| 첫 연습 테이블 | 본인 홀카드·팟·현재 액션을 해당 시점에만 짚기 | 서버가 유효한 플레이 액션을 수락 |
| 한 가지 조작 습득 | 체크 가능한 프리셋에서 체크를 직접 수행, 이후 선택은 열어 두기 | 정해진 학습 행동 완료 |
| 마무리 | 배운 것 하나 + 다음 행동 하나 | 스토리 계속/자유 플레이 선택 |

로비 안내와 테이블 안내를 한 번에 긴 강제 투어로 만들지 않는다. 첫 성취까지 2~3분은 테스트 목표이지 현재 측정값이 아니다. 사용자가 누르지 않았는데 시간 경과나 ‘다음’ 버튼만으로 조작 완료 처리하지 않는다. 모든 입력은 기존 서버 권위 이벤트를 통한다.

구현 시 위치는 실제 요소의 경계로 계산하고 모바일 키보드·스크롤·리사이즈에 맞춰 재배치한다. 대상이 렌더되지 않거나 연결이 끊기면 안내를 안전하게 내려놓고 복구 후 이어간다. 안내를 건너뛰기/다시 보기가 가능해야 한다. 가리키는 컨트롤은 키보드로도 조작 가능해야 한다.

강제 액션과 학습용 턴 보류는 개인 프리셋 수련에서만 한다. 일반 멀티플레이어 테이블의 시계는 안내 때문에 멈추지 않는다. 그 화면은 액션을 가리지 않는 짧은 도움말만 사용한다. 기존 서버 `expectedHandNumber`/`expectedActionSeq`, ack 잠금, 재접속 계약을 유지한다.

안내를 보는 동안 안내 문단을 또 붙이지 않는다. [NN/g의 맥락형 도움말 연구](https://www.nngroup.com/articles/onboarding-tutorials/)도 관련 행동 시점의 안내와 다시 찾을 수 있는 도움말을 권한다. 스포트라이트를 붙이는 것 자체가 학습 효과를 보장하지 않으므로, 두 번째에는 안내 없이 같은 조작을 찾는지 확인한다.

## 5. 보상·경제 현황

아래 경제 값은 `game-config/registry.ts`의 기본값이다. 운영자가 무배포로 변경할 수 있으므로 실제 운영 유효값과 지급 분포는 별도 확인이 필요하다. 이번에는 운영 DB를 조회하지 않았다.

| 항목 | 현재 기본값/카탈로그 | 성격 |
|---|---:|---|
| 신규 프로필 | 지갑 10,000칩 | 최초 1회 |
| 일일 무료 | 지갑 1,000칩 | KST 하루 1회 수동 수령 |
| 챕터 첫 완주 | 지갑 500칩 | 12챕터 각각 1회 |
| 챕터 S등급 | 지갑 300칩 | 각 챕터 첫 S 달성 1회, 재도전에서 달성 가능 |
| 막 완주 | 지갑 1,000칩 | 4개 막 각각 1회 |
| 오늘의 수련 3문 | 지갑 100칩 + 출제 히로인 인연 5 | 개방 후 KST 하루 1회, 도장 XP 없음 |
| 수련 과제 | 과제당 도장 XP 100, 하루 3개 | 직접 칩 보상 없음 |
| 재도전 지원 | 잔액 800 미만이면 2,000까지 보충 | 활성 예치 없음, 하루 최대 3회, 4시간 간격 |
| 아레나 경기권 | 초기 2장·일일 2장·보유 상한 10장 | 지갑 칩과 분리 |

연습 테이블과 스토리 라이브 테이블의 플레이 스택은 지갑과 무관하다. 하지만 수련 보상 카탈로그의 ‘연습 칩’은 `StoryRewardService.#grantChips()`에서 **실제 지갑에 적립**한다. 이 명칭은 ‘지갑 칩’으로 고치는 것이 우선이다. 지급 내역도 ‘첫 완주 +500 / 첫 S +300’처럼 원인별로 표시한다.

스토리는 칩 외에도 도장 XP·인연·칭호·카드백·펠트·CG 등이 있다. 예를 들어 Ch1 첫 완주는 도장 XP 100 + 등급 보너스(A 20/S 50), 선택 파트너 인연 30이며 재도전은 XP 20 + 등급 보너스다. 반복 XP와 최초 한 번의 칩/인연을 합쳐 ‘매번 같은 보상’처럼 설명하지 않는다. 결과 화면은 대표 해금 하나를 크게 보여 주고 나머지는 펼쳐보기로 정리한다.

### 800칩의 실제 구매력

기본 지갑 입문방 Sakura Lounge는 25/50, 최소 40BB=2,000칩, 100BB=5,000칩이다. 무료 Practice Dojo의 10/20과 혼동하지 않는다. 사용자 생성 방은 별도 조건을 가질 수 있다.

| 금액 | 지갑 입문방 BB 환산 | 최소 바이인 2,000 대비 |
|---|---:|---:|
| 첫 완주 500 | 10BB | 25% |
| 첫 완주+S 800 | 16BB | 40% |
| 일일 무료 1,000 | 20BB | 50% |
| 신규 10,000 | 200BB | 최소 바이인 5회 또는 100BB 바이인 2회 |

800칩은 일일 수령의 80%이며 기본 지갑방의 최소 입장액도 채우지 못한다. 사용자 피드백에는 수치 근거가 있다. 다만 한 번 받는 학습 보상은 희소 아이템·학습 성취까지 포함하므로 칩 금액만으로 전체 가치를 확정할 수는 없다.

카탈로그 합계는 첫 완주 `12×500=6,000`, S `12×300=3,600`, 막 완주 `4×1,000=4,000`, 총 **13,600칩**이다. S 없이 전체 완주는 10,000칩, 한 막의 최대는 3,400칩이다. 일일 무료 14회는 14,000칩이다. 반복 학습을 장려하는 보상과 아무 플레이 없이 수령 가능한 칩의 역할을 정렬할 필요가 있다.

또한 잔액 **800~1,999칩**은 기본 지갑방 최소 입장액보다 낮지만 구제 대상도 아니다. 무료 연습이나 더 낮은 사용자 방은 가능하므로 전체 게임 이용 불가와는 다르지만, 기본 지갑방으로 돌아오는 길에는 틈이 있다.

### 추천 정책과 실험 후보

1. 무료 연습의 진입은 항상 보장한다. 경제를 조이기 위해 학습을 막지 않는다.
2. 구제 기준을 입문 지갑방의 최소 입장 조건과 연결한다. 현재 기본값 기준으로는 잔액 2,000 미만→2,000 보충이 검토안이다. 활성 예치·횟수·간격 제한은 유지한다. 지원 횟수와 하루 지급액 변화를 먼저 계산한다.
3. 일일 무료 1,000은 당장 줄이지 않는다. 초기에는 가독성·명칭·입장 공백부터 고친다.
4. 칩 상향 실험 후보는 첫 완주 1,000 / 첫 S 500 / 막 완주 2,000이다. 12챕터 최대 26,000칩, S 없이 20,000칩, 한 막 최대 6,500칩으로 현재보다 총 12,400칩 증가한다. 한 막 완료로 100BB 지갑 입문을 경험하는 목적에 연결한다. 첫 챕터 하나만으로 최소 입장액이 생기는 안은 아니므로 그렇게 홍보하지 않는다.
5. 오늘의 수련은 100→200~300칩을 별도 실험할 수 있다. 300이면 30회 완료자 기준 현행보다 6,000칩이 더 발행된다. 챕터 상향과 동시에 적용하지 않는다.
6. 새 사용자·기존 완료자의 형평성을 정한다. 현재 카탈로그/지급 영수증은 불변이므로 기존 항목 금액을 직접 덮어쓰기보다 새 버전의 차액 보상 항목을 멱등 지급하는 방식이 필요하다. 이전 보상 회수는 하지 않는다.

### 돈이 나가는 곳도 함께 계산

- 지갑 캐시의 기본 레이크는 플랍 이후 팟의 5%, 핸드당 최대 5BB다. 실제 시간당 소각액은 팟 규모와 핸드 수 없이 계산할 수 없다.
- 지갑 Sit & Go 참가비는 1,500+수수료 150이며 1,500은 참가자의 상금 풀이다. 바이인 전체를 소각으로 세지 않는다.
- 인간끼리의 승패는 인간 전체 합계에서는 이전이다. 예치/반환 역시 발행·소각이 아니다.
- 봇 상대 손익은 봇 은행과 인간 지갑 사이의 흐름이므로 인간 경제에 순유입/순유출을 만든다. 레이크만 보고 균형을 판단하지 않는다.
- 개인 잔액은 지갑만이 아니라 진행 중 예치까지 함께 봐야 한다.

다음 수치 확정에 필요한 것은 KST 날짜별 발행 사유 합계, 구제 대상/수령 비율, 봇 상대 순손익, 레이크·수수료 합계, 신규 이용자의 첫 30분 후 잔액·0칩 도달 비율, 챕터 완료 시간이다. 관리자/QA 프로필은 제외한다. 기존 [9월 8일 분석](retention-analysis-2026-09-08.md)은 지갑 부족만을 이탈 원인으로 단정할 수 없다고 명시한다. 이 문서의 작은 표본과 대용 지표를 현재 제품 전체의 원인 분석으로 확대하지 않는다.

## 6. 포커 아레나: 경쟁 대상을 분명하게

### 현재 구현

6인 SnG, 동일 시작 스택 1,500, 5경기 배치, 숨은 MMR, 주간 그룹 승강, 4주 시즌이 이미 있다. 1~6위 점수는 100/60/35/15/5/0이며 누적한다. 공식전은 인간 최소 2명으로 봇을 섞을 수 있고, 대기 60초 뒤 혼자이면 무료 수련을 제안한다. 이미 있는 기능을 신규 개발로 다시 계획하지 않는다.

모든 순위 점수가 비음수라 공식 순위는 실력뿐 아니라 경기 수에 크게 좌우된다. 예를 들어 2위 10회는 600점, 우승 5회는 500점이다. 경기권 공급은 상한을 줄 뿐 이 차이를 없애지 않는다. 인간 수가 다른 혼합전과 봇 전용전의 성적도 동일한 인간 실력 지표로 취급하면 안 된다.

### 경쟁안 비교

| 안 | 경쟁 대상 | 장점 | 한계/추천 |
|---|---|---|---|
| 공식 SnG 랭크 | 상대 수준을 반영한 여러 경기의 순위 성과 | 기존 서버·MMR 활용, 설명이 쉽다 | 인간 매칭 밀도와 충분한 표본 필요. 장기 중심축 |
| 주간 도장 챌린지 | 동일 봇 조건의 제한된 세션에서 얻은 순 BB | 동시에 접속하지 않아도 경쟁, 현재 캐릭터·봇 강점 활용 | 운과 봇 공략의 영향. 초기 비동기 실험 추천 |
| 수련 정확도 경쟁 | 공통 학습 문제의 첫 시도 성과 | 학습과 직접 연결 | 정답 공유·외부 도구·고정 정답 암기 문제. 우선 개인 숙련 기록으로 |

현재 이용 규모에는 **아레나 안의 주간 도장 챌린지**를 작은 프리시즌 실험으로 두는 것이 현실적이다. 기존 분석에서 개인 핸드의 87.9%가 다른 인간 없이 봇 상대였으나, 이 값은 과거 관측이며 현재 동접을 직접 측정한 것은 아니다. 공식전 대기·성립률을 함께 보고 최종 선택한다. 별도 메인 메뉴는 만들지 않는다.

### 주간 도전 실험의 구체안

- 시작 100BB, 같은 블라인드·봇 버전·라인업 규칙. 한 세션 최대 20핸드, 첫 3세션을 집계한다. 총 60핸드는 사용자 플레이 길이를 확인하기 위한 후보이지 필수 출시 규모가 아니다.
- 점수는 집계 세션의 실제 `종료 스택−시작 스택`을 BB로 환산해 합산한다. 공식전 지갑과 분리된 전용 스택이며 충전·재구매는 없다.
- 최고 성적 3개를 골라내는 방식은 무한 재도전 우위가 생기므로 사용하지 않는다. 세션 시작 시 순번을 서버에 확정하고, 중간 종료로 불리한 기록을 삭제할 수 없게 한다. 파산은 해당 세션 종료다.
- 3세션 미완료자는 진행 기록으로 보이고 주간 확정 순위에서는 분리한다. 중단은 같은 세션으로 복귀하며, 정상적인 이탈/시간 초과와 서버 장애 무효 처리를 구분한다.
- 덱은 각 경기에서 기존 보안 셔플을 유지한다. 모두에게 동일한 고정 덱/시드를 재사용하면 먼저 플레이한 사람이 카드를 공유할 수 있다. ‘완전히 공정한 실력 측정’이라고 표현하지 않는다.
- 60핸드는 포커 실력을 단정하기에 작다. 주간 재미 기록으로 명시하고 실제 인간 공식 랭크·MMR에 합산하지 않는다. 동점은 공동 순위로 처리해 먼저 시작한 사람이 이기는 규칙을 피한다.
- 보상은 참가/완료 기념과 시즌 칭호·프로필 장식 위주다. 짧은 표본의 상위 순위에 큰 지갑 칩 보상을 몰지 않는다.

### 공식 랭크 정비 방향

공식전은 상대 수준을 반영하는 레이팅 중심으로 검토하되 현재 숨은 MMR을 검증 없이 그대로 ‘실력 점수’로 공개하지 않는다. 혼합전 봇 MMR과 인간 수에 따른 왜곡, 배치 이후 변동성, 최소 집계 경기 수를 리플레이/시뮬레이션으로 확인한다. 초기 20경기 정도를 ‘잠정’ 표시하는 안을 검토할 수 있지만 20경기가 충분하다는 통계적 보장은 없다.

현재 주간 누적 점수는 활동 리그의 의미로 남길 수 있다. 공식 랭크와 함께 사용할 경우 주 지표 하나를 선택하고 다른 값은 상세에 둔다. 5경기씩 동등하게 제한해 합산하는 대안은 이해하기 쉽지만 작은 표본의 운과 필수 참여 부담이 남는다.

지갑 총액/총 획득 칩/단순 핸드 승률/짧은 표본의 BB·100은 메인 랭크에서 제외한다. 지급 보상·스테이크·참가량·폴드 전략 차이로 왜곡된다. VPIP나 공격 횟수도 점수를 위해 나쁜 플레이를 유도한다. 미완성 코치 평가를 전체 전략의 GTO 점수로 포장하지 않는다.

리더보드는 내 순위, 점수, 집계 수, 내 주변 순위부터 보여 준다. 지급 재화나 전체 통계 설명을 목록 행마다 반복하지 않는다. 동일 상대 반복·다계정·협력 플레이와 비정상 기록을 서버에서 추적할 수 있어야 한다.

첫 UI 시안은 5~8명 정도의 초심자/경험자 관찰로 큰 혼란을 찾는다. 이것만으로 통계적 리텐션 개선을 주장하지 않는다. 5초 찾기는 프로젝트 목표이지 검증된 업계 기준이 아니다. 출시 후 같은 버전·유입 경로의 첫 입력/첫 완료와 KST 다음 날 재방문을 본다. 아직 없는 클릭/안내 단계 측정만 최소한으로 보충하고 별도 대규모 분석 대시보드는 만들지 않는다.

외주를 한다면 내부 기능 전부가 끝날 때까지 기다릴 필요는 없다. 로비·테이블·스토리·결산의 정보 순서와 핵심 행동을 먼저 고정한 뒤, 이 네 화면의 모바일 시안과 공통 컴포넌트·상태별 디자인을 발주 범위로 삼는다. 첫 계약은 로비와 테이블 두 화면의 유료 파일럿으로 결과를 확인하는 안이 적절하다. 이번 작업에서는 업체 선정·연락·비용 확정은 하지 않았다.

초안에서 다음으로 선택할 것은 캐릭터 감성 유지 정도와 로비 시안 방향이다. 경제 상향 수치와 아레나 신규 모드는 UI 변경에 묶어 자동 적용하지 않는다.

## 8. 후속 승인에 따른 구현 (2026-09-09)

사용자가 추천 방향의 일괄 진행을 승인해, UI·행동형 안내·수련 보상·주간 도전 구현을 같은 배치로 진행했다. 위 1~7절은 변경 전 조사와 후보를 기록한 내용이며, 확정된 수치는 다음과 같다.

| 항목 | 변경 전 | 적용 정책 |
|---|---:|---:|
| 챕터 첫 완주 | 500 | 1,000 지갑 칩 |
| 첫 S등급 추가 | 300 | 500 지갑 칩 |
| 막 완주 추가 | 1,000 | 2,000 지갑 칩 |
| 12챕터·4막 최대 합계 | 13,600 | 26,000 (S 제외 20,000) |
| 일일 무료 / 오늘의 수련 | 1,000 / 100 | 동일 |
| 재도전 지원 기본 기준 | 800 미만 | 2,000 미만 → 2,000까지 |

첫 완주1,000은 현재 가장 낮은 지갑 테이블 BB50의20BB, 하루 무료 지급1회분이다. S 추가500은10BB, 막 완주2,000은40BB로 해당 테이블 최소 바이인1회분이다. 이는 보상의 의미를 분명히 하는 초기 정책이며, 체류 시간·발행량과 실제 리텐션 개선을 아직 입증한 값은 아니다. 과제 보상은 기존처럼 XP이며 칩으로 합산하지 않는다.

원본 지급액과 영수증을 보존하고 v41의 별도 차액 보상500/200/1,000을 기존 reconcile 트랜잭션으로 지급한다. 기존 완주자도 자격에 맞는 차액만 한 번 받는다. 기존 관리자가 낮은 구제 목표를 설정했던 경우에는 과거의 암묵적 기준800을 명시해 충돌을 방지하고, 명시적 설정은 바꾸지 않는다. 기본 구제 횟수3회·4시간 간격·활성 에스크로 차단은 유지한다.

모바일 레퍼런스 적용: 작혼의 큰 모드 이름과 캐릭터/기능 구분은 짧은4탭과 주 행동 버튼으로, 클래시 로얄의 모드 선택은 한 곳의 탐색으로, 포켓의 필요한 위치에서 여는 Guide는 도움말 재열기와 실제 버튼의 짧은 안내로 옮겼다. 캐릭터 이미지를 새로 생성하거나 외부 게임의 에셋을 복제하지 않았다. 화면마다 반복하던 설명·그라디언트·강조 테두리를 줄이고 지갑 보상과 테이블 연습 스택의 이름을 구분한다.

주간 도전은 아레나 내부의 무료 봇 도전으로 확정했다.100BB·최대20핸드·첫3세션의 순BB 합계,3세션 완료자 공동순위, 지갑·경기권·MMR과 분리한다. 기존 공식전 누적점수는 활동 리그로 유지한다. 짧은 표본의 결과를 전체 실력 평가로 표시하지 않는다.
